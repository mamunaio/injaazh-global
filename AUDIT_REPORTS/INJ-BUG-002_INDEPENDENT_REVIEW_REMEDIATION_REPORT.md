## 1. Executive Summary

An independent code review of the approved Stage 2 implementation for `INJ-BUG-002` identified three specific findings:
1. **Finding 1 (High Priority): Client Bundle Data Leakage** — `components/InsightsClient.tsx` imported `getAllInsights()` directly inside a `"use client"` component, bundling all 9,191 words and complete section models of the seven canonical articles into the client JavaScript bundle for `/insights`.
2. **Finding 2 (High Priority): Markdown Rendering Deficiencies** — `components/ArticleViewClient.tsx` treated article section content as raw text separated by newlines, leaving bold (`**text**`), italic (`*text*`), inline code (`` `code` ``), fenced code blocks, lists, blockquotes, and mathematical formulas (`$formula$`, `$$formula$$`) unparsed or literally rendered.
3. **Finding 3 (Medium Priority): Category Filter Logic Flaws** — `components/InsightsClient.tsx` rendered `posts[0]` unconditionally in the featured hero banner regardless of the selected category, duplicated `posts[0]` in the grid when filtering by its category, and lacked a resilient empty state.

All three findings have been remediated with zero regressions to the approved article content, statutory citations, metadata, canonical URLs, or visual design. The remediation has been verified against the full test matrix (TypeScript, ESLint, Next.js 16 production build of 104 static pages, runtime audit suite with 162 assertions, and client bundle analyzer).

## 2. Finding 1 Remediation — Client Bundle Decoupling

### 2.1 Problem Analysis
In the initial Stage 2 release, `components/InsightsClient.tsx` included:
```tsx
import { getAllInsights } from "@/lib/insightsData";
const canonicalArticles = getAllInsights();
```
Because `components/InsightsClient.tsx` is marked `"use client"`, Turbopack bundled the entire `insightsData.ts` module closure into the client chunk for `/insights`. This inadvertently exposed internal section content, full legal citations, and raw article text to clients navigating to the article index page.

### 2.2 Solution Implemented
1. **Typed Data Transfer Object (`InsightCardDTO`)**:
   Defined a minimal interface in `lib/insightsData.ts` containing strictly the 7 fields necessary for card rendering:
   ```ts
   export interface InsightCardDTO {
     slug: string;
     title: string;
     excerpt: string;
     category: string;
     date: string;
     readTime: string;
     image: string;
   }
   ```
2. **Server-Side Data Accessor**:
   Added `getInsightCards(): readonly InsightCardDTO[]` in `lib/insightsData.ts`. It maps the frozen article store to shallow card records, completely omitting `sections`, `overview`, `keyTakeaways`, `author`, `socialImage`, and statutory legal bodies.
3. **Server Component Retrieval**:
   In `app/insights/page.tsx` (an async Server Component), `getInsightCards()` is called at server render time:
   ```tsx
   export default function InsightsPage() {
     const cards = getInsightCards();
     const categories = [
       "All",
       ...Array.from(new Set(cards.map((c) => c.category))),
     ];
     return (
       <>
         <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }} />
         <InsightsClient posts={cards} categories={categories} />
       </>
     );
   }
   ```
4. **Client Component Decoupling**:
   `components/InsightsClient.tsx` no longer imports `getAllInsights`. It receives `posts: readonly InsightCardDTO[]` and `categories: readonly string[]` as props.

## 3. Finding 2 Remediation — Secure Zero-Dependency Markdown Renderer

### 3.1 Problem Analysis
In `components/ArticleViewClient.tsx`, section text was split on `/\n\s*\n/` with simple regular expressions for lists and blockquotes. This had several severe defects:
- Fenced code blocks (`http` in Article 3, `typescript` in Article 6) were broken by blank lines or rendered as plain paragraphs with literal backticks.
- Block math (`$$T = a + b \cdot \log_2(n + 1)$$`) and inline math (`$v_g = c / N_g$`, `$\le 0.1$`, `$1 - \beta$`) rendered as unstyled plain text.
- Bold (`**...**`), italic (`*...*`), and inline code (`` `...` ``) were not parsed into semantic tags.
- Any attempt to use standard third-party libraries (e.g. `marked`, `react-markdown`) would risk bundle bloat or dependency misalignment.

### 3.2 Solution Implemented
Implemented a custom, pure-React, zero-dependency Markdown parser and AST renderer directly in `components/ArticleViewClient.tsx`:

1. **Block Parser (`parseMarkdownBlocks`)**:
   Tokenizes raw section markdown into typed AST block structures:
   - **Fenced Code Blocks:** Detects ```` ```(\w*) ```` through ```` ``` ````. Renders syntax-styled terminal containers with language badges (`HTTP`, `TYPESCRIPT`) and horizontal scrolling.
   - **Block Math:** Detects `$$formula$$` (single-line or multi-line). Renders centered mathematical specification containers with cyan monospace styling (`#00E5FF`) and KaTeX-like visual framing.
   - **Blockquotes:** Detects `>` lines. Renders stylized quotes with purple accent borders (`#6324FC`) and recursive inline markdown.
   - **Ordered & Unordered Lists:** Parses `1. ` and `- ` items with continuation line support. Renders styled `<ol>` and `<ul>` elements with custom markers.
   - **Paragraphs:** Renders semantic `<p>` tags with leading and tracking tuned to match editorial styling.

2. **Recursive Inline Parser (`renderInlineMarkdown`)**:
   Safely processes text nodes without regex concurrency corruption (creating a fresh RegExp per invocation):
   - **Inline Code:** ` `code` ` -> `<code className="text-[#00E5FF] font-mono bg-white/[0.08] ...">`
   - **Inline Math:** `$formula$` -> `<code className="text-[#00E5FF] font-mono bg-[#6324FC]/10 ...">`
   - **Bold + Italic:** `***text***` -> `<strong className="font-semibold text-white"><em className="italic">`
   - **Bold:** `**text**` -> `<strong className="font-semibold text-white">`
   - **Italic:** `*text*` -> `<em className="italic text-white/90">`
   - **Safe Hyperlinks:** `[text](url)` -> `<a href="..." rel="noopener noreferrer">` (strictly validating `https://`, `http://`, or `/`; blocking `javascript:` and data protocols).

3. **XSS Immunity Guarantee**:
   - Zero use of `dangerouslySetInnerHTML` for article content or user inputs.
   - All text content is rendered as React string children, automatically HTML-escaped by React's virtual DOM.
   - Dangerous URI schemes (`javascript:`, `vbscript:`, `data:`) are rejected and converted to plain text.

### 3.3 Test Evidence
- **All 7 Articles Processed:** 159 blocks and 714 inline tokens parsed with 0 errors (`scratch/test_full_pipeline.js`).
- **Unit Test Suite:** 8/8 assertions passed (`scratch/test_markdown_renderer.js`).

## 4. Finding 3 Remediation — Category Filter & Featured Hero Logic

### 4.1 Problem Analysis
In `components/InsightsClient.tsx`:
1. The featured hero banner was hardcoded to `posts[0]` unconditionally. When a user filtered by "Design" or "Technical SEO", `posts[0]` (an "Engineering" article) remained visible in the hero banner.
2. If a user filtered by "Engineering", `posts[0]` was displayed in the featured hero banner AND again in the article grid, creating an unsightly duplicate.
3. Empty categories lacked an explicit clean empty state.

### 4.2 Solution Implemented
Refactored state and filtering logic in `components/InsightsClient.tsx`:
```tsx
const isAll = activeCategory === "All";

// Filter matching posts by category
const matchingPosts = isAll
  ? posts
  : posts.filter(
      (post) => post.category.toLowerCase() === activeCategory.toLowerCase()
    );

// Hero banner appears ONLY if "All" is active OR posts[0] belongs to activeCategory
const showFeatured =
  matchingPosts.length > 0 &&
  (isAll || posts[0]?.category.toLowerCase() === activeCategory.toLowerCase());

const featuredPost = showFeatured ? posts[0] : null;

// Grid posts: exclude featuredPost when it is shown in the banner; otherwise show all matching
const gridPosts = featuredPost
  ? matchingPosts.filter((p) => p.slug !== featuredPost.slug)
  : matchingPosts;
```

Additionally:
- **Clean Empty State:** When `!featuredPost && gridPosts.length === 0`, an elegant empty state is rendered with a "View All Briefings" reset button.
- **Key Stability:** Updated grid items from `key={post.id}` to stable `key={post.slug}`.

### 4.3 Test Evidence
Verified across all 5 operational scenarios (`scratch/test_category_filter.js`):
1. **Scenario 1 ("All"):** Hero banner displays `posts[0]`; grid displays remaining 6 articles. Total 7 articles, 0 duplicates.
2. **Scenario 2 ("Engineering" — matching posts[0]):** Hero banner displays `posts[0]`; grid contains 0 duplicates. Total 1 article, 0 duplicates.
3. **Scenario 3 ("Design" — non-matching posts[0]):** Hero banner is hidden; grid displays `neuro-design-psychology`. Total 1 article, 0 duplicates.
4. **Scenario 4 (All other categories):** Hero banner is hidden; grid displays strictly the category's articles.
5. **Scenario 5 (Empty/Unmatched Category):** Hero banner and grid cleanly hidden; responsive empty state is displayed.
